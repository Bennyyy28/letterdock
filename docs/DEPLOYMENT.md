# Deployment and configuration

Run one Letterdock instance per owner. The app uses a standard Next.js Node server; it does not require the original author's hosting platform, account, or domain.

## Configuration reference

All variables are server-only. Restart after changing them.

| Variable | Purpose |
| --- | --- |
| `LETTERDOCK_ORIGIN` | Exact trusted origin, such as `https://mail.yourdomain.com`. No path, credentials, query, or fragment. HTTP is accepted only for literal loopback hostnames. |
| `LETTERDOCK_PASSWORD_HASH` | Salted scrypt hash generated by `npm run setup`. Never use a plaintext password here. |
| `LETTERDOCK_SESSION_SECRET` | Separate random signing secret generated by setup. Keep it stable across restarts, private, and distinct per deployment. |
| `LETTERDOCK_OWNER_NAME` | Optional display name; defaults to `My inbox`. |
| `RESEND_API_KEY` | Dedicated Full Access key. Keep it in private server secrets or a gitignored `.env.local`. |
| `RESEND_INBOXES` | JSON array of up to ten inboxes. Each has unique `key`, UUID `id`, `name`, and `address`; `description` is optional. |
| `LETTERDOCK_SENDING_INBOX` | Empty means sending/drafts are disabled. Otherwise one configured inbox key; there is no request-selected sender. |

Mailbox keys must start with a lowercase letter and contain only lowercase letters, numbers, or hyphens, up to 32 characters. `all`, `constructor`, and `prototype` are reserved. Changing a key changes its identity in the UI; prefer stable keys. The displayed email address is operator-supplied; verify it matches the Resend inbox ID before enabling sending.

## Node server

From a clean checkout, run `npm ci`, `npm run setup`, and edit `.env.local`. Use a password manager to save the generated login password. Then:

```sh
npm run build
npm start
```

By default this listens on `127.0.0.1:3000`. Use a process supervisor for restarts, and place an HTTPS reverse proxy or private gateway in front of the loopback listener. Set `LETTERDOCK_ORIGIN` to the exact address you open on your devices. For example, opening `http://127.0.0.1:3000` while configured for `http://localhost:3000` will fail write origin checks intentionally.

For a managed Node/Next hosting service, configure these variables using its private server environment/secrets UI and follow its Next.js startup instructions. Do not expose them to a static client build, preview deployment, contributor fork, or browser. No deployment credentials are included in this repository.

Production must use HTTPS away from loopback. Verify the browser receives a Secure, HttpOnly, SameSite Strict session cookie. The app does not implement MFA; use a private access gateway or identity-aware proxy if you require it. Follow the [Next.js self-hosting guide](https://nextjs.org/docs/app/guides/self-hosting) for production hosting.

At the proxy, restrict accepted hosts to your configured domain, rate-limit `/api/auth/login`, cap request sizes and timeouts, and avoid logging password bodies, mail bodies, cookies, or authorization headers. A process-level ten-attempt login limit is only a backstop: it can reset on restart and is not shared across replicas. Use a single instance unless you add shared rate limiting for login and Resend requests. Add HSTS at your HTTPS edge when the domain is ready for it.

## Password and session rotation

For an installation using `.env.local`:

```sh
npm run setup -- --rotate-auth
```

This replaces only the password hash and session signing secret, keeps the Resend configuration, and prints a new random login password. Save it privately, then restart the app. Existing sessions and review tokens will no longer be valid. For a managed secret store, perform generation in a private local checkout and replace the two auth values in that store, then restart/redeploy. Never copy `.env.local` into a repository or attach it to a support request.

To revoke mail access, revoke the dedicated key in Resend and replace the server secret. Empty `LETTERDOCK_SENDING_INBOX` and restart to disable all draft/send operations in Letterdock. Anyone with a Full Access provider key can bypass the app, so keep it separate from agents and other apps.

## Data, backups, and updates

Mail and drafts remain in Resend. Letterdock holds UI state in memory and does not create a separate message database. This is not an email backup; follow your provider's retention policy and your own backup plan. Server memory and browser memory still contain messages while you use the app.

Keep configuration in a password manager or private encrypted backup. Update from a reviewed release, run the checks in CONTRIBUTING.md, rebuild, and restart. Review dependency advisories regularly; passing `npm audit` is a point-in-time result, not an ongoing guarantee.
